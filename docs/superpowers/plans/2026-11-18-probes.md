# Probes Folder Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `probes/` folder of runnable TypeScript scripts exercising the library's public API (`Cc2652pZigbeeCoordinator` + `NodeSerial`) against a real dongle, with an explanatory README.

**Architecture:** One dash-cased script per probe, sharing a single port-selection helper (`probes/open-port/open-port.ts`). Probes import `../src/…` directly; Node ≥ 24 runs them with native TypeScript stripping. No probe touches the internal layers.

**Tech Stack:** Node.js ≥ 24 (native TS stripping), `@thingmate/zigbee` ability classes, existing `NodeSerial`/`NodeSerialPort` adapter (serialport).

**Spec:** `docs/superpowers/specs/2026-11-18-probes-design.md`

## Global Constraints

- English content only (AGENTS.md); French is for conversation with the user only.
- Dash-cased file and folder names; one `.ts` file per folder; named exports only; no default exports; no barrel files.
- `erasableSyntaxOnly` is on: no `enum` — use `as const` objects + type unions.
- `verbatimModuleSyntax` is on: import types with the `type` keyword.
- Generics are `G`-prefixed PascalCase; `readonly` as much as possible; no `private` keyword (use `#`-fields).
- Probes import only `Cc2652pZigbeeCoordinator` and `NodeSerial`/`NodeSerialPort` from `../src/…`.
- Zero new dependencies; probes are never executed by `yarn fb:test` (vitest covers `src/` only).
- `process` globals are available (`types: ["node"]`).

## Review Focus

- No matching port (usbipd not attached): `NodeSerial.requestPort` throws `no serial port matches the requested filters` — the probes must let this message surface untouched, and `probes/README.md` points to `windows-wsl-usb-setup.md`. Pinned by: Task 2's manual-run step for `list-ports.ts` (expected error text when the dongle is detached).
- Permission denied on open (missing `dialout` group): serialport surfaces its own error — README documents `sudo usermod -aG dialout $USER` + `wsl --shutdown`. Pinned by: README content step in Task 4.
- Ctrl+C during `monitor.ts`: the port and the observation resource must close cleanly instead of leaving a stale handle; next probe run must reconnect. Pinned by: Task 3's manual-run step for `monitor.ts` (run twice in a row, second run must start).
- `config-write.ts` destructive path: the re-commissioning warning must print BEFORE any write, and the non-destructive default (no arguments) must never touch network parameters. Pinned by: Task 3's code step (warning printed before `config.write.call`) and manual-run step.
- Multiple matching ports: `NodeSerial.requestPort` throws naming the count — README tells how to disambiguate (a single dongle must be attached). Pinned by: README content step in Task 4.

### Task 3: smoke, monitor and config-write probes

**Files:**

- Create: `probes/smoke.ts`
- Create: `probes/monitor.ts`
- Create: `probes/config-write.ts`

**Interfaces:**

- Consumes: `requestCoordinatorPort()` (Task 2), `Cc2652pZigbeeCoordinator` (`readDeviceState`, `config.read/write.call(signal, config?)`, `permitJoin.call(signal, duration)`, `command.observe.call(signal)` → `ListenerResource` with `listen`/`close`, `command.send.call(signal, frame)`, `close()`), `ZigbeeCoordinatorConfig` `{channel, panId, extPanId (bigint), key (Uint8Array), txRadio}`.
- Produces: nothing (leaf scripts).

- [ ] **Step 1: Implement `probes/smoke.ts`**

Sequence: `readDeviceState` → `config.read` (printed: channel, panId, extPanId, key hex, txRadio) → `permitJoin(60)` → observation window of ~15 seconds (frames printed as `device/endpoint cluster 0x… command 0x… payload <hex>`) → `permitJoin(0)` → resource closed → `coordinator.close()`. Prints one line per stage.

- [ ] **Step 2: Implement `probes/monitor.ts`**

Opens the observation resource, prints every received frame in the same format as `smoke.ts`, and installs a `SIGINT` handler that closes the resource and the coordinator before exiting with code 0.

- [ ] **Step 3: Implement `probes/config-write.ts`**

Manual argument parsing over `process.argv.slice(2)`: `--channel=<11..26>`, `--pan-id=<0x…|dec>`, `--ext-pan-id=<hex up to 16 digits>`, `--key=<32 hex digits>`. Flow: `config.read` → merge provided values over the read configuration (missing fields stay unchanged) → when any network parameter changed, print a prominent re-commissioning warning (network re-formed, devices must be paired again) BEFORE calling `config.write` → `config.write` → `config.read` again to print the applied configuration → `close()`. Without arguments the write is non-destructive (radio tuning only). Invalid values print the usage and exit 1.

- [ ] **Step 4: Type-check and format**

Run: `yarn fb:check`
Expected: PASS.

- [ ] **Step 5: Manual run with the dongle attached**

Run: `node probes/smoke.ts` (expect config printed, network opened then closed), then `node probes/monitor.ts` twice in a row (expect a clean stop on Ctrl+C both times), then `node probes/config-write.ts` with no arguments (expect the same configuration printed, no re-commissioning).

- [ ] **Step 6: Commit**

```bash
git add probes/smoke.ts probes/monitor.ts probes/config-write.ts
git commit -m "feat(probes): smoke, monitor and config-write probes"
```
